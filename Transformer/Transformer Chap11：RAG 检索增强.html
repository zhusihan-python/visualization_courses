RAG 系统生产级 5 大工程优化手段

1. 缓存层 (Query Cache)

使用 Redis 对高频相似 Query 建立向量缓存，提升响应速度并降低 LLM Token 成本。

2. 混合检索 (Hybrid Search)

融合 Dense Vector (语义) 与 BM25 (关键词精确匹配)，基于 RRF 算法合并评分。

3. 父子文档切分 (Parent-Child)

小 Chunk (如 150 字) 用于向量精准匹配，命中后提取大 Parent Block (如 800 字) 送给 LLM。

4. 假想文档扩展 (HyDE)

先让 LLM 生成假想回答，再用假想回答的向量去检索数据库，弥补 Question-Answer 向量差距。

5. 动态重叠 (Dynamic Window)

根据文本标点符号 (如句号、段落换行) 动态调整 Window 边界，防止句中硬切断。

第 11 章：全书总结与最佳实践 CheckList (12 Key Takeaways)

1. 垃圾进，垃圾出
解析阶段清洗掉导航栏、页眉页脚与脚本，是后续高召回率的前提。
2. Heading Stack 上下文
切块时拼装 Markdown 标题层级路径，可避免孤立段落丢失重要限定语。
3. 重叠窗防止断句
保留 10%-20% 的 Overlap Sliding Window，可防核心实体关键词被斩断。
4. 双塔召回加速
Bi-Encoder 将 Chunk 预先向量化，在向量数据库中极速进行 Top-K 余弦搜索。
5. 交叉精排提高精度
Cross-Encoder 将 Query 与 Chunk 拼接计算 Full Attention，大幅度减少虚假召回。
6. 拒答门控防幻觉
设定 τ 阈值拦截低匹配度查询，是消除生产环境中幻觉的最有效手段。
7. Recall@K 指标
衡量检索模块是否涵盖了回答问题所需的全部关键知识片断。
8. MRR 倒数排名
衡量正确答案出现的优先顺位，首位命中得分最高 (1.0)。
9. LLM-as-Judge 自动化
利用大语言模型自动评估 Faithfulness (忠实度) 与 Relevancy (相关度)。
10. 父子 Chunk 结合
以小 Block 做 Vector Search，以大 Block 做 LLM Context，兼顾精准度与上下文。
11. 混合检索 Hybrid
合并向量检索与关键词 BM25，有效解决专有名词、单号等精确定位问题。
12. 闭环基准测试
建立固定 Evaluation Dataset，任何切块与模型调整均需通过基准测试验证。
