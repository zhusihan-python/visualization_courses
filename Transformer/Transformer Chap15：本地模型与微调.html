15.2 HuggingFace Transformers 本地衔接与生成采样诊所

掌握 AutoConfig / AutoTokenizer / AutoModelForCausalLM 的本地加载参数，避开 do_sample=False 导致温度失效的经典陷阱。

from_pretrained() 四大核心加载参数

torch_dtype = torch.bfloat16
GPU 上首选 BF16（省一半显存且不溢出），纯 CPU 上用 float32。
device_map = "auto"
由 accelerate 自动把模型层切分分配到可用 GPU 显存 / CPU 内存。
quantization_config = BitsAndBytesConfig(...)
开启 4bit NF4 量化（需 CUDA + bitsandbytes），7B 显存从 14G 降到 3.5G。
attn_implementation = "flash_attention_2"
Ampere 及以上架构 GPU 开启 FlashAttention-2，长文本速度翻倍且省显存。

          15.3 LoRA / QLoRA 微调数学原理与显存压缩剧场
        

        

          核心假设：微调时的权重变化量 ΔW 是低秩的。冻结庞大的原始权重 W0，只训练两个极小的低秩旁路矩阵 A 与 B。
        

      


      
      

        

          

            
Part A: LoRA 低秩分解矩阵与 全量 / LoRA / QLoRA 显存实时对比

            

              公式：h = W0x + αr B · A · x（以 7B 模型单层 4096 × 4096 线性层为例）
            

          

          

            单层参数压缩 256× (仅 0.39%)
          

        


        
        

          

            

              低秩维度 r:
              r = 8
            

            
          

          

            

              缩放系数 lora_alpha:
              α = 16 (scale = 2.0)
            

            
          

          

            
            
          

        


        
        

          
        


        
        

          

            

              ✨ 性质 1：初始化时零偏移 (B = 0)
              torch.allclose == True
            

            

              lora_A 随机高斯初始化，lora_B 严格初始化为全 0 矩阵。因此训练第 0 步时 B · A · x = 0，输出与原模型完全一致，保证微调平稳起步而不破坏预训练知识。
            

          


          

            

              🚀 性质 2：部署前可合并 (Zero Overhead)
              W' = W₀ + (α/r)BA
            

            

              训练完成后，把 (α/r) · B @ A 直接加回原权重 W₀ 导出为标准模型权重。线上用 Ollama / vLLM 推理时零额外延迟，且一个基座可挂载多个不同业务 LoRA 适配器（每个仅几十 MB）！

Part D: 第 15 章 12 条核心要点总结矩阵

        

          

            
1. 本地部署的四大收益

            
数据不出内网、边际成本趋近 0、局域网低延迟、模型版本完全可控。

          

          

            
2. Ollama vs vLLM 选型

            
个人开发/CPU/离线用 Ollama；对外高并发生产 API 必选 vLLM。

          

          

            
3. vLLM 两大核心加速

            
PagedAttention 消除 KV 显存碎片，Continuous Batching 把 GPU 利用率提到 80%+。

          

          

            
4. Q4_K_M 性价比之王

            
7B 模型 Q4 仅需 ~6GB 显存且质量损失很小；Q2 质量断崖下降不推荐。

          

          

            
5. OpenAI 兼容层零迁移

            
Ollama 与 vLLM 均提供 /v1/chat/completions，旧代码只改 base_url 即可切换。

          

          

            
6. do_sample=False 陷阱

            
Transformers 中贪心解码时 temperature 和 top_p 完全不会生效。

          

          

            
7. LoRA 省 87% 训练显存

            
冻结原权重只训低秩旁路 B·A，7B 训练显存从 112GB 骤降至 14.3GB。

          

          

            
8. B=0 初始化零偏移

            
矩阵 B 全 0 初始化保证加载 LoRA 初始输出与原模型 100% 一致，训练更稳。

          

          

            
9. 权重合并推理零开销

            
部署前执行 W' = W₀ + (α/r)BA 合并，线上推理无任何额外延迟。

          

          

            
10. QLoRA 单卡 8G 训 7B

            
NF4 4bit 量化基座 + 二次量化 + BF16 LoRA 适配器，消费级显卡即可微调 7B。

          

          

            
11. 知识用 RAG，风格用微调

            
动态知识库千万别用微调硬塞，优先顺序永远是 Prompt → RAG → Fine-tuning。

          

          

            
12. 数据质量决定微调上限

            
500~2000 条高质量精修对话远胜海量脏数据，且 epoch 控制在 1~3 轮防过拟合。
