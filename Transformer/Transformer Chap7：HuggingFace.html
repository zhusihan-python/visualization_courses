7.3 LoRA 低秩微调数学实验室与合并验证器

剖析 Low-Rank Adaptation 降维打击原理：在极低秩子空间下微调大模型并零开销部署

Part A: 低秩矩阵分解解剖实验室

h = W0 x + ΔW x = W0 x + α/r B A x
Param Optimization Engine
左侧: 冻结巨型基座矩阵 W0 (d × d) | 右侧: 低秩 Bottleneck 矩阵 A (r × d) 与 B (d × r)
模型隐层维度 d (d_model): 4096
LoRA 秩 r (rank): 8
缩放缩放因子 α (lora_alpha): 16
冻结基座参数量 (Single Layer): 67.11 M
LoRA 可训练参数量: 0.26 M
可训练参数占比 (%): 0.39%
空间压缩比 (Compression): 256.0 ×
输出缩放系数 (α / r): 2.00
不同规模模型全微调 vs LoRA 显存需求 (Adam 优化器) 显存降低 ~87%
7B Model (Full FT ~112 GB VRAM vs LoRA ~16 GB VRAM)

Part B: LoRA 两大核心性质互动验证

点击观察为何 LoRA 初始化不会破坏预训练权重，以及部署时如何做到零延迟开销

初始化阶段: 矩阵 B 设为全零 (Zero Initialization)

在微调第 0 步，矩阵 A 采用高斯分布初始化，而矩阵 B 采用全 0 初始化。因此 ΔW = B × A = 0。 这意味着模型初始状态的输出与未微调的基座模型完全 100% 相同，不会产生任何突发的随机输出扰动！

ΔW = B (all zeros) × A (gaussian) = 0 ➔ h_step0 = W₀ x + 0 = W₀ x

7.5 本地 LLM 量化显微镜与 Ollama vs Transformers

深入 4-bit Normal Float (NF4) 正态量化原理，并厘清 Python 生态与 C++ Ollama 生态的分工边界

Part A: INT8 / INT4 / NF4 量化阶梯显微镜

切换不同量化模式，观察网格点如何在正态分布的高密度区域密集分布

当前量化模式: 4-bit Normal Float (NF4)
均方量化误差 (MSE Error): ~ 0.0012 (极低)
7B 模型显存开销: 3.5 GB
为什么 NF4 远优于标准 INT4？
大语言模型权重高度拟合零均值 Gaussian 正态分布。传统 INT4 均匀划分刻度会在两端稀疏处浪费大量的量化阶梯；而 NF4 采用分位数非均匀量化，把 16 个刻度集中压在 0 附近，实现了信息熵最大化！

本章要点核心总结 (Takeaways)

01. AutoFactory
AutoClass 实现了参数配置与具体架构代码的完全解耦。
02. 离线零下载
调试模型网络结构时，使用 AutoConfig 比直接加载权重快上百倍。
03. Sampling 陷阱
必须显式声明 do_sample=True，调节 temperature 才能真正生效。
04. Attention Mask
变长批处理必须依赖 Mask 将 PAD token 点积强制抹平为 -∞。
05. LoRA 降维
在极低秩空间分解 ΔW = B × A，保存微调梯度的巨额显存开销。
06. 零扰动 Start
B 初始化全 0 确保微调在 step 0 时模型行为与预训练完全一致。
07. 部署无开销
推理前将 (α/r)BA 权重大块加回 W₀，消除多余矩阵乘法延迟。
08. Softmax 温度
T 缩放 Logits 改变概率平坦度，Top-p 核采样动态截断长尾。
09. NF4 正态量化
利用权重正态分布特性做非均匀分位数量化，精度损失最小。
10. 混合生态部署
HF 负责训练微调，转化 GGUF 后利用 Ollama 实现高效 C++ 本地部署。
