          17.3 12-Factor 密钥管理与 SIGTERM 优雅停机剧场
        

        

          容器发版重启时，线上往往还有 20 个用户正在接收 SSE 流式回答。直接 kill -9 会让所有用户前端瞬间报错断流，必须正确响应 SIGTERM 优雅停机。
        

      


      
      

        

          

            
Part A: 暴力强杀 (SIGKILL) vs 优雅停机 (SIGTERM) 停机时序对比

            
切换两种停机方式，观察容器收到发版更新信号后，正在进行的 SSE 流式对话与新流量的命运

          

          

            
            
          

        


        

          
        


        

      


      
      

        

          
🔐 1. 严禁把 API Key 打进镜像或 Git

          
永远通过运行时环境变量（env_file / K8s Secret / 云 KMS）注入 OPENAI_API_KEY。仓库里只提交脱敏模板 .env.example。

        

        

          
👤 2. 容器内切换非 root 用户运行

          
Dockerfile 里创建普通用户 USER appuser，即使 Agent 工具被 Prompt 注入攻破，攻击者也拿不到宿主机高危权限。

        

        

          
⚙️ 3. 启动即 Fail-Fast 校验配置

          
用 pydantic-settings 在启动第 1 秒强校验必填环境变量；缺 Key 立刻报错退出，绝不等到凌晨 3 点用户提问时才崩溃。

        

        

          
💾 4. 有状态数据挂载 Named Volume

          
容器随时会被销毁重建。Chroma 向量索引、Redis AOF 与审计日志必须挂载宿主机卷或独立托管云数据库，做到应用层完全无状态。

Part D: 第 17 章 12 条生产部署核心要点总结

        

          

            
1. 多阶段构建瘦身

            
构建阶段装 gcc 编译依赖，运行阶段只拷贝虚拟环境与代码，镜像缩小 80%+。

          

          

            
2. 依赖层先于业务代码

            
先 COPY requirements.txt && pip install，再 COPY app/，改代码 3 秒完成缓存重建。

          

          

            
3. 必配 .dockerignore

            
排除 .venv、.env、.git 与本地大缓存，防止镜像膨胀和明文密钥泄露。

          

          

            
4. Compose 内网隔离

            
Redis / 向量库绝不暴露公网端口，仅通过 Docker 内部服务名安全通信。

          

          

            
5. Nginx 关闭缓冲保 SSE

            
必配 proxy_buffering off、proxy_http_version 1.1 与 300s 读超时，防流式卡顿或断连。

          

          

            
6. 非 root + 只读最小权限

            
容器内切换普通用户 appuser 运行，极大收敛 Agent 工具被注入后的爆炸半径。

          

          

            
7. 运行时注入密钥

            
遵循 12-Factor 原则，配置与代码彻底分离，用 pydantic-settings 启动即校验。

          

          

            
8. SIGTERM 优雅停机

            
Dockerfile 使用 exec 格式 CMD，收到 SIGTERM 后先摘流量、等存量 SSE 推完再退出。

          

          

            
9. 有状态数据持久化卷

            
向量库与 Redis 挂载 Named Volume 或用云托管实例，确保应用容器随时可销毁扩容。

          

          

            
10. CI/CD 挂接 Eval 门禁

            
上线前自动跑 Lint + pytest 契约单测 + 黄金集 Eval 回归，守住质量红线。

          

          

            
11. 金丝雀灰度控风险

            
换模型或改 Prompt 先切 10% 真实流量观测点踩率与账单，确认健康再全量。

          

          

            
12. 生产上线检查清单

            
HTTPS 证书 + 限流熔断 + 预算告警 + 结构化 Trace 日志齐备，才算真正 Production Ready！
