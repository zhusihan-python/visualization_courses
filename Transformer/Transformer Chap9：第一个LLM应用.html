9.4 结构化输出三档进阶与 Pydantic 校验防线

模型本质是概率 Token 生成器，直接要求输出 JSON 存在高风险。生产环境必须建立以 Function Calling + Pydantic 为核心的双重解析防线。

当前模式：Tier 3 生产推荐级

Pydantic 校验防线实测 (SentimentPayload Model)

Rules: label ∈ ['positive','negative','neutral'], 0 <= confidence <= 1
Raw Tool Call Arguments String: 
{ "label": "positive", "confidence": 0.95, "summary": "用户对新界面非常满意" }
方案 Tier JSON 语法合规率 Schema 字段强约束 类型与枚举校验 适用场景
Tier 1: Pure Prompt ~70% (易带 markdown/客套话) ❌ 无保证 ❌ 无保证 仅限 Demo / 简单实验
Tier 2: JSON Mode 100% (保证可解析) ⚠️ 依赖 Prompt 指导 ⚠️ 易出现类型混淆 轻量化结构化提取
Tier 3: Function Call + Pydantic 100% (API 级约束) ✅ 严格按 Schema 填充 ✅ Pydantic 客户端强类型校验 生产级高可靠 API 交付
核心法则： 模型输出在工程层面永远是“不可信输入（Untrusted Input）”。任何进入核心业务逻辑的数据，客户端必须使用 Pydantic 进行第二次强类型反序列化校验。

6 大生产级工程设计要点

1. asyncio.to_thread 异步化

同步 SDK 调用不可阻塞 FastAPI/Streamlit 主事件循环，统一包进线程池。

2. 请求前历史截断 (Trim First)

在 payload 组装的最早期即执行 trim_messages，确保不超时上报无用长文。

3. 末帧 Usage 防空指针

处理 choices: [] 空数组帧，避免 chunk.choices[0] 触发 IndexError 崩塌。

4. 异常分级与重试捕获

细分 RateLimitError (429)、APIConnectionError 与 AuthenticationError (401)。

5. 模版化 Pricing 计费表

维护模型单价字典，实现每次请求自动累计 Prompt 与 Completion 美金开销。

6. 离线 MockTransport 单元测试

通过 httpx.MockTransport 拦截网络请求，零 Token 消耗完成 CI/CD 自动化测试。
