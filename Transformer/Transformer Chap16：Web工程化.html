SSE vs WebSocket 选型对比

          

            
              

                对比维度
                SSE (Server-Sent Events)
                WebSocket
              

            
            
              
通信方向服务端 → 客户端（单向推送）全双工双向通信

              
底层协议纯 HTTP，天然兼容代理/防火墙独立 ws:// 协议，需网关升级

⚠️ 线上 SSE 最常见的 3 个坑

          
    
            
  • Nginx 缓冲吃掉流式：Nginx 默认攒满 4KB 才转发，响应头必须加 X-Accel-Buffering: no！
    • 
            
  • 浏览器原生 EventSource 只支持 GET：带 JSON body 和 Authorization Header 的 POST 流式请用 fetch() + getReader()。
    • 
            
  • 流中途报错无法改 HTTP 状态码：流开始后状态码已是 200，异常必须作为 event: error 帧推送给前端。

🧅 FastAPI 中间件洋葱执行顺序

          

            
1. CORS Middleware → 放行指定前端域名（生产禁用 allow_origins=["*"] + credentials）

            
2. Request-ID & Access Log → 注入 X-Request-ID 贯穿全链路日志

            
3. Bearer Auth (Depends) → 用 hmac.compare_digest 校验 API Key

            
4. Rate Limiter → 按租户/IP 扣除令牌，超限直接返回 429

            
5. Route Handler → 执行 RAG / Agent 业务并返回统一响应体

          

        


        

          
💾 多轮会话状态存储选型（为什么不能只用全局 dict？）

          

            

              1. 内存 dict（仅限单进程 Demo）：
              Uvicorn 开 --workers 4 多进程后，第 1 轮落在 Worker A，第 2 轮落在 Worker B 直接失忆，且进程重启清空！
            

            

              2. Redis + TTL（生产热会话首选）：
              多 Worker / 多机共享上下文，自带过期时间（如 24h 自动淘汰防内存泄漏），读写延迟 < 1ms。
            

            

              3. PostgreSQL（长期审计与历史回看）：
              持久化归档用户完整历史会话与点赞/点踩反馈，供离线 Eval 评测复用。

            🔧 CPU 密集型任务（如本地 Embedding / PDF 解析）：
            不要在 async def 里直接跑，用 await asyncio.to_thread(model.encode, texts) 丢给线程池，或直接把路由声明为普通 def 让 FastAPI 自动托管线程池。
          

          

            📦 耗时异步任务（如上传 100 页 PDF 建索引）：
            接口不要干等！用 BackgroundTasks（或 Celery/ARQ）立即返回 HTTP 202 Accepted + job_id，前端轮询任务进度。

Part D: 第 16 章 12 条核心要点总结矩阵

        

          

            
1. Lifespan 托管重资源

            
Embedding 模型、向量库、AsyncClient 必须在 lifespan 启动时加载一次，关闭时优雅释放。

          

          

            
2. Pydantic 强契约校验

            
用 Field 约束长度、温度范围与枚举值，非法请求在进业务前自动返回 HTTP 422。

          

          

            
3. 区分 /health 与 /ready

            
/health 查进程存活；/ready 查模型和依赖就绪，加载未完成返回 503 防止流量提前打入。

          

          

            
4. SSE 响应头防缓冲

            
流式接口必加 X-Accel-Buffering: no 与 Cache-Control: no-cache，防止 Nginx 攒包。

          

          

            
5. 监听客户端断连止损

            
生成器循环内检查 await request.is_disconnected()，用户关网页后立刻中止上游扣费。

          

          

            
6. 文本对话首选 SSE

            
SSE 纯 HTTP 更易部署与负载均衡；只有需要随时语音打断的全双工场景才上 WebSocket。

          

          

            
7. 令牌桶精准限流

            
按 API Key / IP 实施 Token Bucket 限流，超限返回 429 + Retry-After 保护上游额度。

          

          

            
8. 多 Worker 必用 Redis 会话

            
多进程部署下内存 dict 会导致上下文丢失，热会话应存入 Redis 并配置 TTL 自动过期。

          

          

            
9. X-Request-ID 贯穿全链路

            
中间件为每次请求生成唯一 ID 并写入响应头与日志，前后端排查线上故障秒级对齐。

          

          

            
10. 严防 async def 阻塞

            
异步路由内绝不能用 requests 或 time.sleep；CPU 密集计算用 asyncio.to_thread 卸载。

          

          

            
11. 长耗时任务 202 异步化

            
文档批量入库等耗时操作交给 BackgroundTasks / 任务队列，接口立即返回 202 + job_id。

          

          

            
12. 依赖注入解耦单测

            
用 Depends 注入 LLM 客户端，配合 dependency_overrides 让 pytest 零费用离线跑通全量测试。
