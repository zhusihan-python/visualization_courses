二分查找：为什么看一个数，就敢扔掉一半？

升序数组 [3, 7, 11, 18, 25, 31, 42]（下标 0–6）里找一个数，不逐个翻，凭什么一次排除半段？ 学完你能：① 预测下一次候选范围；② 指着图上的证据，说明为什么这样排除不会漏掉目标。

交互自学微课 · 约 6 分钟 · 数组与目标均为教学示例 · 下标从 0 开始

先记一句能用的规则

比中间：小了 → 扔左半、往右找；大了 → 扔右半、往左找；相等 → 找到了。

  • 中间数 < 目标：目标只可能在右半段。左半连同中间数那一格整段排除，lo 移到 mid+1。
  • 中间数 > 目标：目标只可能在左半段。右半连同中间数那一格整段排除，hi 移到 mid−1。
  • 中间数 = 目标：找到，答案就是下标 mid。

为什么安全：数组升序 ⇒ 被扔那一段的每一个数都 ≤ 中间数（于是都 < 目标），或都 ≥ 中间数（于是都 > 目标）——目标不可能藏在那里。这句话，本课会让你亲手验证。

总结：回到开场问题

凭什么敢扔一半？

以 E1 为证：18 < 25 且数组升序 ⇒ 主例图上灰色段的证据条写着「0..3 都 ≤ 18 < 25」——那一段每一个数都比 25 小，25 不可能藏进去，整段扔掉不会漏。排除的依据写在图上，不是猜。

两次运行的轨迹

找 25：候选 7 → 3 → 1 项，第 3 次比较相等 ⇒ 下标 4。
找 24：候选 7 → 3 → 1 → 0 项，范围为空 ⇒ 不存在。
两问都只用了 3 次比较，规则一条没变——变的只是目标。

适用条件（可推广）

任何升序数组、任意目标值都适用；“比较一次扔一段”的安全性始终来自升序；候选范围为空 ⇔ 目标不存在。mid = ⌊(lo+hi)/2⌋ 只是约定；重复元素本课未涉及。

简化与示例说明：数组与目标 25 / 24 均为教学示例；「一步 / 第几次」是比较次数计数，不代表真实耗时； mid = ⌊(lo+hi)/2⌋，向下取整只是约定；本课数组无重复元素，不涉及无序数组（预测题追问中的乱序数组仅作反例，不真正运行）。
