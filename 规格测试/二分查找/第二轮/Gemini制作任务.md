# Gemini 制作任务 · 二分查找为什么能排除一半候选项

请直接制作一节中文交互式自学微课。使用本文提供的数据和规格，离线独立设计页面、讲解、可视化和练习。交付可运行的课程及简短设计说明。

## 1. 本次课程任务

| 项目 | 要求 |
| --- | --- |
| 主题 | 二分查找为什么能排除一半候选项？ |
| 学习者 | 刚学过数组和下标，第一次学习二分查找。 |
| 学习目标 | 给出一次比较后，学生能预测下一次的候选范围，并指着画面中的证据解释为什么可以安全排除其余位置。 |
| 给定数据 | 升序数组 `[3, 7, 11, 18, 25, 31, 42]`，下标从 0 开始。 |
| 主例和迁移题 | 主例查找 `25`。迁移题沿用同一数组，改为查找 `24`。 |
| 使用场景 | 学生独立在浏览器中操作，预计 6 分钟。 |

请交付以下两个文件。若当前界面只能回复文本，请分别标出文件名，给出各自完整、可直接保存的内容。

1. **`index.html`**　可离线直接用浏览器打开的单文件课程。将所需样式、脚本和图形放在文件内。
2. **`设计.md`**　按第 4 节的五项顺序提供简短分镜和设计说明，并附第 6 节逐项自检。实际操作过的项目写明观察结果，其余项目写明验证步骤与预期结果。

以下为本次采用的通用制作规格。第 5 节的打印队列仅用于演示如何填写设计稿，本次交付主题以第 1 节为准。

把一个学习者熟悉的事件做成一节可以观察、推理和验证的课。学完后，学习者应能解释一次关键变化，并从图、记录或对象详情中指出依据。适用于有参与者、时序、状态变化或因果关系的内容，例如网络通信、任务调度和业务流程。

## 2. 课程设计规则

1. **从一个能讲完的事件切入。** 写明谁在做什么、开始时处于什么状态、怎样算结束。把学习目标写成可观察的表现，例如“能根据报文指出浏览器何时可以发送网页请求”。“了解 HTTP”不足以指导选材。
2. **按学习者需要解释的变化分段。** 每段用动词短语命名，并用一句话回答“这一步解决什么问题”。只要后续动作的条件发生改变，就值得考虑分段。多个底层动作可以同属一个教学阶段，浏览器发起请求这样的本地动作也可以占一段。
3. **在术语起作用时引入它。** 先交代角色面临的问题，再给出机制名称和可观察结果。例如，笔记本刚入网时还没有可用地址，接下来发出的广播让 DHCP 的作用有了上下文。端口、规范编号等查阅信息可放入概览或详情。
4. **用共享情境组织相关课节。** 系列课程给出每课要回答的问题、所需前置知识和可接续的课节。能比较的两课，固定角色、任务和可比条件，明确第一个分叉点。例如 HTTP 与 HTTPS 都打开同一个网页，学习者可以追踪 TLS 握手从哪里加入、随后在线路上能读到什么。
5. **用能显出因果的案例。** 当机制负责处理异常时，先让异常发生，再展示谁看到了什么信号、采取了什么动作、结果如何。TCP 的可靠传输可以从一次丢段讲起。当教学问题只需要正常路径时，保留最短的完整案例即可。
6. **用证据收尾。** 结尾回到开场问题，用本次运行的结果作答。在关键转折处设一道预测题，或在结尾设一道解释题。答案应指出具体事件、字段或状态；展示完成进度仅表示学到了哪里。

**安排一节微课时**，先写一句学生能复述、能用于预测的规则，再安排一次分步观察、一次学生亲手作答，最后只改变一个条件，让学生说明原判断是否仍然成立。按给定时长挑选解释这一变化所需的概念。遇到真实工程场景，可用“你会检查哪个字段来决定下一步”收尾。

## 3. 可视化与交互规则

| 学习者要解决的问题 | 视图与编码 | 设计约束 |
| --- | --- | --- |
| 谁参与，经过哪里？ | 用关系图或空间图表示角色、连接和移动方向。 | 同一角色在同一场景中位置稳定；突出当前路径，把角色名放在对象附近。 |
| 谁先行动，谁在等谁？ | 用时序图、泳道或前后状态图表示顺序、依赖和等待。 | 标出箭头方向或状态差异。若间距只表示先后，写明这一点；若要比较时长，提供刻度或数值。 |
| 依据是什么？ | 用事件记录保存有解释力的字段，选择某条后显示详情。 | 图、记录、讲解共用事件标识。颜色可区分类别，名称、符号或线型也须能独立表达差异。 |
| 怎样看清一个转折？ | 给连续过程提供暂停、单步和回看；跨度大的过程可加调速或按阶段跳转。 | 单步的单位要明确。回退或重播后，当前阶段、图中状态和记录选中项应一致。 |

只选能回答本课问题的视图。默认先展示阶段和关键变化，精确数值、原始字段或完整结构按需展开。动画结束后，应有可以停下来比较的图或记录。若多次底层事件被合并、时间被压缩、非关键事件被省略，在相应位置标明范围，并保留回答验收题需要的证据。

**让动作对应到状态。** 在图旁写明本步是谁对什么做了什么，并显示一项足以解释结果的变化，例如“B 到达，等待队列由 0 项变为 1 项，打印机仍归 A 使用”。多方传递消息时，可用固定的参与者列、生命线和带名称的方向箭头；内部处理标在本列，丢失或超时标在实际中断处。讲数组区间时，直接在数组上标边界和候选数即可。区分当前与已完成的步骤，让学习者可从已变化的对象定位到对应事件和理由。

**按作答进度揭晓。** 首次预测时，把题干、必要线索和作答控件放在同一操作区。列出允许看见的证据，以及提交后才出现的结果。图中标签、箭头、步骤导航、记录表和详情卡遵守同一规则。作答后揭晓变化，复盘时可跳转到已揭晓的任一步。若有正常与异常两条路径，在第一个分叉事件对齐两图，标明改变的条件及它首先影响的状态。

**按学习目标选择练习。** 一节微课优先选能直接检验目标的一种形式。

| 学生需要展示的能力 | 合适的操作 | 可核查的反馈 |
| --- | --- | --- |
| 判断并解释 | 先选结果并圈出支持它的对象或字段，再揭晓 | 分别检查结论与依据。为“选对但理由错”准备一个能区分错因的追问。 |
| 应用规则 | 对一组相近输入逐项选择结果，包含一个边界值 | 标出违反的条件，允许只重做错项。 |
| 实现算法 | 补全一个能运行的函数，预测一个边界输入的输出 | 用正常和边界用例核验，失败时显示输入、预期与实际结果。 |
| 诊断多组件问题 | 对照正常与异常记录，指出第一个分叉事件 | 核对异常输入、首个受影响的组件及下游结果；综合项目可用端到端测试重现。 |

## 4. AI 的交付格式

按以下顺序生成设计稿。单课从第 1 项开始；系列课程先附课程地图，列出每课的核心问题、前置知识、主图、练习形式和对照关系。

1. **课程简报。** 学习者、前置知识、开场问题、起止状态、可检验的学习目标，以及必要的假设。
2. **阶段分镜。** 每行填写“阶段编号｜动作标题｜为什么发生｜学习者会看到什么｜关联事件编号”。若只有本地状态变化，直接写出该变化。
3. **事件记录。** 每行填写“事件编号｜顺序或时间｜参与者｜动作｜前后状态或关键字段”。这张表是讲解、图形、交互和答案共用的事实依据。表前注明时间单位和数据来源。实测值注明出处，推算值给出所用条件，模拟值说明示例假设。
4. **画面与操作。** 对每个视图写明“回答的问题｜视觉编码｜选中事件时的反馈”。给关键一步填写“动作｜字段变化前后值｜学生在哪里看到”。说明初始画面、单步粒度、回看行为和必要的简化。若要求可运行 HTML，把步骤讲解贴近交互图，并验证练习入口可用。
5. **学习验证。** 写明练习形式、题目、预期答案、证据位置与可推广的条件。预测题另列“作答前可见｜提交后揭晓｜典型错因与反馈”。给出验收结果；有待核实的数据或机制时，列明受影响的设计。

## 5. 填写示例：为什么短打印任务也要等

**简报。** 面向第一次学习队列的学生。开场问题是“一页的文件 B 和正在打印的文件 A 用同一台打印机，B 到达后多久能开始？”教学模型采用先到先服务，每秒打印一页，一个任务连续打印到结束，切换耗时为零。以下时间和页数均为示例。

| 阶段与教学目的 | 事件 | 打印机与队列状态 |
| --- | --- | --- |
| 开始打印，建立起点 | E1 · 0 秒，四页的 A 到达并开始 | 打印机处理 A，等待队列为空 |
| 新任务入队，区分“到达”和“开始” | E2 · 1 秒，一页的 B 到达 | A 还有三页，B 在队首等待 |
| 交接，找到 B 获得打印机的条件 | E3 · 4 秒，A 完成，B 开始 | 打印机从 A 转给 B，等待队列变空 |
| 结束，区分等待时间和执行时间 | E4 · 5 秒，B 完成 | 打印机空闲，B 共等待三秒、打印一秒 |

**画面与操作。** 用 A、B 两条时间轨道，共用 0 至 5 秒的刻度。斜线区段标“等待”，实心区段标“打印”，让只看灰度图的学生也能区分。初始画面是空闲的打印机；单步每次推进一个事件。选中 E2 时，时间指针停在第 1 秒，B 出现在队首；回退到 E1 时，B 应从队列中消失。示例把同一时刻的完成与交接合并为 E3。

**验证。** 在 E2 暂停并提问：“如果 B 从一页改成两页，开始时间会变吗？指出决定它何时开始的事件。”预期答案是仍在第 4 秒开始。E2 表明 B 已在等待，E3 表明 A 此时释放打印机。在给定规则下，B 的页数改变自己的完成时间，前一个任务的剩余工作量决定它还要等多久。

首次作答只显示截至第 1 秒的轨道、A 剩三页和每秒一页的速率，记录表也停在 E2。学生先选开始时间，再选择决定因素“前一个任务尚需的时间”或“自己的页数”。若时间选对却选了后者，追问“保持 B 两页，如果 A 此刻只剩一页，B 又会在哪一秒开始？”学生可据此修正理由。提交后画到第 4 秒，点 B 的开始位置可回到 E3，查看等待队列从一项变为空、打印机从 A 转给 B。变式中 B 的完成位置应延长到第 6 秒。

## 6. 交付前验收

交付时给每项附上一处能复查的依据，例如“E2 至 E3 对应 B 的三秒等待”。分镜能够验证因果、编码和预期状态；需要运行成品才能确认的交互，标为“待实测”，并写出操作和预期结果。

- **因果**：选一个转折，能否指出前置条件、变化和结果？阶段标题是否足以让学习者复述过程？
- **可追溯**：任选一题，能否从答案定位到事件，再在画面或记录里找到同一份证据？时长、计数和汇总值能否从示例重算？
- **可读**：暂停动画、隐藏颜色后，能否识别参与者、动作方向或状态差异？不同视图是否各自回答了具体问题？
- **可回看**：停在关键事件并切换视图，是否仍选中同一事件？退一步再前进一步，能否恢复相同的画面和记录？在分镜阶段写出预期状态，在实现阶段按该路径操作验证。
- **简化透明**：学习者能否知道哪些数据是示例、哪些动作已合并、时间轴如何读？这些取舍是否保留了得出结论所需的信息？
- **预测与反馈**：从首次学习入口停在预测点，依次打开记录、详情和导航，确认学生只能看到推理线索。分别提交“结论错”和“结论对但依据错”，核对反馈能否指出下一步应检查的条件。复盘时再点一个发生变化的对象，核对它能否带回揭晓该变化的事件。
