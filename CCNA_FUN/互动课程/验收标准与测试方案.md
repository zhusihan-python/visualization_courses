# CCNA 互动课程 · 验收标准与测试方案

本文件给出 50 项任务的测试设计。17-S2 已有[修订版与复测记录](试作/17-S2/评审.md)，其余小节按[制作排期](制作排期.md)执行。技术推演、浏览器功能测试和真实学习者试学分别记录，三者验证的问题不同。

## 1. 怎样接一项任务

测试者领取一个 ID，例如 08A。在[章任务书](章节任务/08.md)读场景、两条固定线索和本轮唯一变化的字段。从[用例文件](验收用例.json)按 ID 取三例。M 是主例，V 是迁移，B 是第三个边界或反例。M、V 经过未来成品的学生入口执行；B 默认由独立评审者纸笔重算、在设计讨论或课后陌生题中核验。若成品允许输入自定义场景，再对 B 做界面实测。学生的预测页不可读出验收答案或用例表。

约定四个教学时刻，制作人可用不同界面实现。① 初态只给本题成立的条件；② 取得决定性的字段，停住让学生选结果和依据；③ 提交正确后高亮命中字段与作用范围，画出状态变化；④ 回看已经发生的事件。每个时刻有稳定事件 ID。图形、讲解、日志与控件按同一状态显示。若任务要求点图选证据，应在作答区列出这一项，并显示已选对象。

## 2. 单项验收标准

| 编号 | 要回答的问题 | 可观察的通过标准 | 发现问题时保留的证据 |
| --- | --- | --- | --- |
| A1 机制正确 | 主例、变式和边界的结论怎么得出？ | 评审者独立演算 M、V，数值、单位、作用域、前提和终点与画面一致；B 的期望也经单独推演。规则若有例外，题面条件明确 | 写下输入、运算或匹配过程、期望与实际，注明教材节号 |
| A2 预测有效 | 学生是自己作出判断的吗？ | 预测时有足够证据，结果仍未执行。依次看主图、标题、详情、日志、迁移标签和导航，不能提前看见系统已经选着哪条路。选择题中的候选结果作为选项正常可见 | 提交前的事件 ID、可见字段、日志末行 |
| A3 直接提交 | 按题面完成后能前进吗？ | 仅完成所有明示动作，直接提交正确答案即进入指定结果。漏答明确指出缺项。结论错与依据错有不同反馈；修改后能继续；若有追问，选项可操作且能提交 | 记录完整点击顺序、按钮状态、反馈和提交后的事件 ID |
| A4 图能讲清因果 | 图本身能说明决定发生在哪里吗？ | 盖住长段说明，评审者能实际指出决定性读数、它对应的链路或字段范围、改变的状态。对象在前后画面位置稳定，线型、符号或文字支持灰度阅读 | 同一事件的前后两帧；写明在图上分别指向哪三处 |
| A5 迁移与回看 | 变式究竟改变了哪一项？ | 从迁移初态重走，固定线索与主例一致，只改卡片指定字段。首次分叉前可预测，提交后再出现新结果。点已观察字段和已发生变化的对象，分别回到各自事件；前进、后退、重置保持一致 | 对照 M、V 的分叉事件；保存“结果 → 起因 → 结果”路径 |
| A6 可读与交付 | 学生能独立打开并操作吗？ | 单项直接打开可运行。桌面主证据、题目、提交可就近对照；手机正常阅读顺序为观察、作答、提交。整页无横向溢出，关键标注不重叠。键盘可到达并提交所有必做动作 | 记录窗口宽高、浏览器、缩放、必要滚动和实际完成路径 |

A1–A3 的实质错误、A5 的提前揭晓或错误跳转、任何阻断核心作答的问题，应修正后复测再交付。A4 或 A6 若导致读错端口、区间或方向，也按影响学习目标的问题处理。轻微留白、非关键措辞可记录后单独优化。验收报告先写“能否完成、图能否解释、状态是否可靠”，需要评分时再附维度分；不以加权总分覆盖已复现的问题。

## 3. 测试执行顺序

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| T01 · 独立核算 | 暂遮住预期列，仅依据任务的输入和教材规则画出 M、V；再做 B | 得到与预期等价的结果和理由。发生分歧时先复核题设和预期本身，不沿用程序输出充当标准答案 |
| T02 · 全新进入 | 直接打开该任务，停在第一次预测；展开详情，从日志、章节入口和迁移入口尝试跳转 | 只见已发生状态及必要线索。比较图例与真实可访问行为，检查表面变灰的按钮是否仍能进入 |
| T03 · 最短正确路径 | 从全新状态只完成题面列出的选择并提交 M；用同样方式提交 V | 学生能进入预期结果；题目、字段、画面和日志的事件一致 |
| T04 · 漏答与纠错 | 用重置后的 M、V 分别试漏一项、结果错、结果对但依据错；随后改正并提交 | 缺项指出缺项，错因提示指向具体字段或条件，已选正确结果可保留；修正可前进 |
| T05 · 分叉时刻 | 并排记录 M、V 的预测前最后一帧和提交后第一帧 | 改变的输入可见，提交前仍未显示实际出口、路由或角色；首次不同结果出现在预定事件 |
| T06 · 追到起因 | 从末帧点一个输入证据，再点一个结果对象；后退并重新前进，最后重置 | 两个对象各自指回相应事件。重播后计数、未知状态和日志恢复；初次学习的未来记录重新锁定 |
| T07 · 画面与设备 | 暂停并做 A4 三问。参考 1280×800 桌面、390×844 手机，另测键盘和记录最长的一步 | 字段与对象一一对应、文字可读、操作可达。手机纵向滚动可接受；记录桌面是否需滚离主图才能提交 |
| T08 · 换情境试学 | 让接受过先修内容的学生独立学一项，再给予未见过的 B 或同难度题；只收首次答案 | 记录是否答对、能否指出证据、完成时间、是否需要提示。不将“点到最后一屏”计作掌握；缺少试学数据时标待试学 |

**可自动化的部分。** 使用浏览器从学生入口触发事件，断言当前事件 ID、已显示的对象集合、选择控件状态、记录上限、判题后状态与重置结果。自动化只用学生可操作的控件。不要直接调用内部“下一步”代替点击；这种测试容易漏掉控件禁用、焦点丢失或隐藏的必做动作。视觉因果、技术解释和学习者表现分别由看图、独立重算、试学验证。

## 4. 一项完整演练：08A 最长前缀匹配

本节为测试示范，均是预期，无实际执行记录。

1. 教材 8.2。输入给出两条已安装路由：192.0.2.128/25 经东口，默认路由经西口。主例目的 .200。独立核算 /25 包含末字节 128–255，因此两条都匹配，/25 更长，选东口。
2. 在预测点只呈现两条候选路由与目的地址。先选“西口”提交，应提示检查 .200 是否也匹配 /25；再选“东口”但给出错误依据，应追问两条匹配项中哪一条更具体。
3. 正确提交后，/25 行、.200 落点和东口箭头同时对应。迁移只改目的为 .40；此时 /25 不匹配，提交后才画西口箭头。
4. 以 .128 做边界探针：它是该 /25 的首地址，按路由匹配会选东口。这道题只问匹配，与是否适合分配给普通主机是两个问题。
5. 让测试者遮住正文指图说出“.200 同时落入哪些区间、为什么东口胜出”。若图上只有一行“东口正确”，可判算法正确，但视觉解释验收不能通过。

## 5. 记录、修复与小节交接

每条结果用一行记录，状态区分“未执行 / 通过 / 未通过 / 修复后通过 / 待试学”。推荐字段如下。

| 小节 / 任务 ID / 版本 | 测试编号与数据 | 环境及初始状态 | 操作 → 预期 | 实际、截图或日志 | 状态及复测 |
| --- | --- | --- | --- | --- | --- |
| 08-S1 / 08A / 待制作 | T03 · 08A-V | 手机 390×844，迁移预测前 | 仅选西口和最长匹配依据 → 出现西口结果 | 待制作后填写 | 未执行 |

按课程地图的小节编号签收。每项任务保留原 ID 及 M、V、B 三个用例。一个小节含两项时，两项分别记录结果；若其中一项为 C，核心任务通过即可交付核心路线，C 标为选做未交付或单独签收。两项均为核心时须分别通过才算该节完成。整节均为 C 时，其进度单列。验收者从小节独立入口进入，还应确认开始状态自足；若链接到后一节，测试不能借此提前查看当前题的结果。

例如 17-S2（17B）答前只能看到 VLAN 和两端允许列表，答后才显示是否可经 Trunk 交付。只要该节通过，就能签收；17-S3（17C，跨 VLAN 路由）可另行制作。章节进度汇总已交付小节和剩余小节，不以整章完成作为测试前提。对共享组件的修复至少回归原失败用例和一个跨章用例；例如 05A 的区间标签改动后，再检查 14B 的通配符区间。纸面技术核对、浏览器验收、学生试学各自标明完成情况。
